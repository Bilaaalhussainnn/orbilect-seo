## Build the navigation around customer tasks

Choose a design that suits your content, then build the service, contact and trust pages first. Write navigation labels in customer language. Use reusable sections and a consistent type scale rather than recreating layouts page by page.

### Set up pages around the customer journey

Define what someone needs to do after arriving: request a quote, review a portfolio or buy a product. Create those paths before choosing elaborate page layouts. Use the design tools to set consistent type, spacing and buttons. Draft content with real prices, scope or service examples where appropriate. Put important public pages in navigation or link them from another relevant page.

## Connect the domain and configure search settings

Confirm where the domain is managed and follow the connection steps shown in Squarespace. Keep any existing email records in place. Set descriptive SEO titles for important pages, add meaningful image text, and inspect the generated sitemap after publication.

### Connect your domain and prepare search settings

Confirm the live primary domain and SSL. Edit SEO titles and descriptions for core pages and set readable slugs. Review image descriptions for informational images and check how social previews look when sharing a page. Open the automatically generated sitemap on the live domain. If you replace an existing site, document old paths and configure URL mappings for addresses that have moved.

## Test the published experience

Open the site on mobile, submit an enquiry and check where it arrives. Verify redirects if replacing a site. Test the canonical hostname and remove any launch restrictions that should no longer apply. Measure contact or purchase completions separately from general visits.

### Check forms, accessibility and mobile layouts

Publish to a preview environment while reviewing forms and shopping or booking flows. Confirm submissions reach the right account and the confirmation instructions make sense. Test the live navigation on a phone and keyboard. Review text on images for contrast and verify that image crops preserve essential content. After launch, connect Search Console and check a few important URLs.

## Choose a template around the content

Prepare the actual services, photography, navigation, and contact requirements before choosing a visual template. Check its mobile presentation with realistic text lengths. A polished template preview may rely on images and copy that do not resemble the business’s material.

## Keep the navigation focused

Group pages by customer need and use clear labels. Put the primary enquiry or booking action where visitors expect it. Avoid hiding essential information inside decorative sections that look attractive on desktop but are difficult to scan on a phone.

## Review page settings individually

Write page-specific titles and descriptions and inspect the published URL. Confirm which pages should be searchable and which should remain private. Use the platform’s current documentation because available controls and menu labels can change between editor versions.

## Prepare images for the actual layout

Crop and compress photography for the spaces where it appears. Check the focal point on both a phone and a wide screen. Do not upload a print-resolution image merely because the editor accepts it; the displayed result rarely needs that original file size.

## Test enquiries and ownership before launch

Send a test form from a signed-out browser and confirm receipt at the business inbox. Verify domain access, billing ownership, and collaborator permissions. Keep a record of the platform settings that must be reviewed whenever the site or team changes.

## Plan redirects before renaming established pages

Make a list of important existing URLs before changing navigation or moving content into a new structure. Identify a relevant destination for each retired page and use Squarespace's URL mapping guidance for the supported redirect pattern.

After publishing, test the old URL directly as well as the menu link. A new navigation item can work while an old link from search or a customer bookmark still leads to a missing page.

[Squarespace: URL mappings](https://support.squarespace.com/hc/en-us/articles/205815308-URL-mappings)

## Treat forms as an operational workflow

A form is only useful when submissions reach the right team and receive a response. Confirm the available storage or notification destination, send a realistic test and check whether staff can identify the service requested.

Provide clear labels and an understandable confirmation message. Ask only for information needed at this stage, and avoid making customers submit the same details twice simply because a notification or handover process is incomplete.

## Keep reusable design choices consistent across pages

Agree a small set of spacing, typography, image and button rules before filling every page. Review how those choices behave with a longer heading, a short description and a page containing more detailed information.

Consistency should help a visitor recognize the next step, not force every page into the same content layout. Use the platform's editing system to support the information rather than repeating decorative sections that add no explanation.

## Prepare an owner-friendly publishing checklist

Create a brief handover covering page edits, image replacement, form checks, account access and the steps used to publish a change. Include an example of a correctly configured service page so future editors have something concrete to follow.

Recheck search settings and old links after structural changes. Ownership of a finished website includes knowing how to maintain it, not just having the login details for an attractive first version.

## A photographer’s launch example

A portrait photographer builds a portfolio, a packages page and a booking page. The packages page answers travel and delivery questions and links to booking. After switching domains, the photographer redirects the old packages URL and tests both booking and a callback request on a phone.

Before launch, review which pages must be public and which areas belong behind restricted access. An unlinked page can still be accessible by its exact address, so use the relevant visibility and indexing controls for material that should be private or excluded. Document who can publish, update domains and change payment information. When possible, get one person who did not build the site to complete the most important task using a small phone and a realistic network connection.

## Common questions

### Can I redesign before changing the domain?

Yes. Keep your public site operating while you review the new design. Schedule the DNS change after confirming redirects and critical forms.

### Should I add a third-party sitemap plugin?

Squarespace generates a sitemap. Test its live output and its coverage before introducing a second source.

### What is the safest way to rename a published page?

Record the old URL and create a mapping to the new path. Update navigation and internal links, then check both URLs in a signed-out session.
